1. ¿Qué es la terminal?

Es una ventana donde, en vez de hacer clic, escribes órdenes y el ordenador responde con texto. Cada orden se llama comando. Escribes el comando, pulsas Intro y se ejecuta.

Linux es el sistema operativo (como Windows o macOS) y casi todo lo que haces con ratón se puede hacer con comandos.

2. El «prompt» y el símbolo $

Lo que ves antes de poder escribir se llama prompt:

lliurex@lliurex-VirtualBox:~/Ejercicios$ ls -l
  • lliurex = tu usuario · lliurex-VirtualBox = el nombre del ordenador.
  • ~/Ejercicios = la carpeta en la que estás ahora (~ es tu carpeta personal).
  • $ = «estoy listo, escribe». En una terminal real no se escribe: ya está puesto.
Pero en el examen sí lo escribes: el profe pide pegar la respuesta empezando en el $. Más abajo, en «Cómo responder».

3. Cómo está hecho un comando

Casi todos tienen tres partes separadas por espacios: comando -opciones argumentos

grepel comando: qué hacer
(grep = buscar texto)
-vopción: cambia cómo lo hace
(-v = «al revés»)
5argumento: con qué
(el texto a buscar)
combinado.txtargumento: sobre qué
(el fichero)
  • Las opciones llevan un guion delante (-l) y se pueden juntar: ls -l -a = ls -la. No se deja espacio entre el guion y la letra.
  • Los espacios importan: separan las partes. cd Ejercicios funciona, cdEjercicios no.
  • Las mayúsculas importan: Notas.txt y notas.txt son ficheros distintos.
  • Si un texto lleva espacios, se pone entre comillas: echo "Hola, Mundo".
  • Si un comando funciona bien, normalmente no dice nada. Solo habla cuando hay algo que mostrar o un error.

4. Carpetas y rutas

Linux llama directorio a las carpetas y fichero (o archivo) a los documentos. Todo cuelga de un único árbol que empieza en / (la «raíz»).

/                  ← raíz
├── home
│   └── lliurex        ← tu carpeta personal (~)
│       └── Ejercicios
│           └── CFGS
├── tmp
├── dev
└── etc

Una ruta es la dirección de algo en ese árbol:

  • Absoluta: empieza por / y vale desde cualquier sitio → /home/lliurex/Ejercicios
  • Relativa: parte de donde estás → Ejercicios/CFGS
AtajoSignifica
.la carpeta donde estás
..la carpeta de arriba (la «padre»)
~tu carpeta personal
/la raíz de todo

5. Cuatro trucos de teclado

  • Tab: autocompleta nombres. Escribe cd Ejer + Tab.
  • ↑: recupera el comando anterior (así no lo reescribes).
  • Ctrl+C: corta un comando que se ha quedado «colgado».
  • clear: limpia la pantalla.
Consejo para practicar: abre una terminal (o una máquina virtual con Linux) y repite los ejemplos. Equivocarse con estos comandos es seguro mientras estés dentro de tu carpeta Ejercicios.

Cómo responder en el examen

MUY IMPORTANTE (palabras del profe): se pega la respuesta a partir del carácter $, incluido. Ojo con los espacios en blanco.
Si la respuesta es ls -l, se responde exactamente: $ ls -l (un espacio entre el $ y el comando).

Esto explica muchos de tus fallos: las preguntas 4.107–4.116, 4.123 y 4.127 tenían el comando bien, pero sin $ delante.

Además, viendo tus fallos (no lo ha dicho el profe, es lo que se deduce)
  • Comillas dobles " ", no simples: cut -d ":" -f1, no cut -d ':' -f1.
  • Sin comillas si no hacen falta: $ echo CFGS >> listado.txt, $ grep 5 combinado.txt. Con espacios sí: $ echo "Hola, Mundo".
  • Ruta relativa y sin barra final: $ cd Ejercicios (no /home/lliurex/Ejercicios), $ mv cursos CFGS (no CFGS/).
  • Lo mínimo que pide el enunciado: $ rm -r CFGS/* (sin la f), $ tree cursos (sin instalarlo en la misma línea).
  • Opciones tal cual: $ ps aux --sort -%cpu (con espacio, sin =).
  • Si el enunciado dice «esto no lo pongas en la respuesta», la respuesta es el siguiente paso (4.067 → $ rm notas.txt).
  • Preguntas de concepto: solo la palabra o número (1, 2, iguales, Distintos, error, l).
  • Única solución sin $ que he visto: 4.132 (ps aux | grep mysql). Si dudas, sigue la regla del profe.

cp4.022

En pocas palabras«Haz una copia». El original se queda donde está. (copy)
cp [-r] origen destino
  • Para copiar una carpeta con su contenido hay que añadir -r (recursivo = «y todo lo de dentro»).

mv4.021, 4.023

En pocas palabras«Cambia de sitio» o «cambia el nombre». Linux usa el mismo comando para las dos cosas. (move)
mv origen destino
  • Si el destino es una carpeta que existe → mueve dentro de ella.
  • Si el destino no existe → renombra.
mv cursos CFGS # mueve "cursos" dentro de "CFGS" mv CFGS/cursos/lenguajes CFGS/cursos/dispositivos # "lenguajes" pasa a llamarse "dispositivos"
Tu fallo (4.021): mv cursos CFGS/ con barra final. La solución es $ mv cursos CFGS.

3 · Redirecciones y tuberías: >, >>, |

La ideaNormalmente el resultado de un comando sale por la pantalla. Con estos símbolos lo desvías: a un fichero (>, >>) o a otro comando (|).
SímboloQué haceEjemplo
>guarda la salida en un fichero. Borra lo que hubiera (o lo crea)echo "Linux es genial" > prueba.txt
>>guarda la salida al final del fichero, sin borrar nadadate >> archivo1.txt · cal >> archivo2.txt
|pasa la salida de un comando como entrada del siguienteps aux | grep ssh
Regla fácil: > = «a un fichero, empezando de cero» · >> = «a un fichero, añadiendo» · | = «al siguiente comando». Después de > siempre va un fichero; después de | siempre un comando.
Una tubería paso a paso
ps aux | grep ssh # 1) ps aux → lista TODOS los procesos # 2) | → "pásale eso al siguiente" # 3) grep ssh → quédate solo con las líneas que contienen "ssh"

Se pueden encadenar varios: cut … | tr … | grep … | sort …. Cada comando trabaja con lo que le deja el anterior.

findlista del profe

En pocas palabrasSi grep busca dentro de los ficheros, find busca los propios ficheros y carpetas (por nombre, tipo…), mirando también en todas las subcarpetas.
find dónde-buscar criterio [acción]
CriterioBusca…
-name "x"por nombre (admite *)
-type fsolo ficheros
-type dsolo directorios (carpetas)
-user nombrelos que pertenecen a ese usuario
find . -name notas.txt # desde aquí (.), un fichero llamado notas.txt find /home -name "*.txt" # todos los .txt bajo /home find . -type d # solo las carpetas de aquí para abajo find . -name "fic*" -exec ls -l {} \; # por cada fichero que empiece por "fic", ejecuta ls -l sobre él ({} = el fichero encontrado)
Ojo: el primer argumento es dónde buscar (. = aquí, / = todo el disco). Pon los patrones con * entre comillas para que los interprete find y no el terminal. No ha salido en tus ejercicios: lo he hecho con lo que explica el PDF.

sort4.046–4.049, 4.059, 4.069–4.071

En pocas palabras«Ordena las líneas». Por defecto ordena de la A a la Z mirando la línea desde el principio.
sort [-opciones] fichero
OpciónQué hace
-k Nordena por el campo número N (columna)
-t ":"dice cuál es el separador de campos. En notas.txt son los :
-nordena como números (imprescindible con notas)
-rreverso: de mayor a menor / de Z a A
sort -k 1 notas.txt # por nombre sort -k 2 -t : notas.txt # por apellido 1 (campo 2, separador :) sort -k 3 -t : notas.txt # por apellido 2 sort -k2 -r -t ":" notas.txt # apellido 1, de Z a A sort -k4 -n notas2.txt | head -n 6 # las 6 notas1 más bajas (campo 4) sort -k5 -n -r notas2.txt | head -n 3 # las 3 notas2 más altas (campo 5)

Tus fallos: olvidabas -t : en notas.txt; escribías -k 2,2 en vez de -k 2; y en notas2.txt (tabuladores) usabas -t':', que ahí no hace falta.

PowerShell · 2 · Manipular y buscar contenido

Write-Outputps31, ps35, ps36, ps40, ps42

En pocas palabras«Muestra este texto». Es el echo de Linux. Para guardarlo en un fichero se le añade | Out-File.
Write-Output "¡Hola, mundo!" # ps31 Write-Output "Primera línea" | Out-File prueba.txt # ps35: crea el fichero Write-Output "Segunda línea" | Out-File prueba.txt -Append # ps36: añade al final Get-Content sintaxis.txt ; Write-Output "COMANDO COMPLETADO" # ps40: dos comandos seguidos con ;
Tu fallo (ps31): usaste Write-Host. El profe quiere Write-Output. (En ps40 te aceptaron Write-Host, pero no te arriesgues.)

El ; separa comandos independientes: se ejecutan uno tras otro.

Out-File (y >, >>)ps32, ps35, ps36, ps42, ps49, ps51, ps59

En pocas palabras«Guarda esto en un fichero». Como en Linux, el > funciona, y el profe dice: > es Out-File y >> es Out-File -Append.
EscribesEquivale aEfecto
comando | Out-File x.txtcomando > x.txtcrea / sobrescribe
comando | Out-File x.txt -Appendcomando >> x.txtañade al final
Get-Content notas.txt -TotalCount 10 | Out-File notas_10.txt # ps49 Get-Content notas.txt, notas_10.txt | Out-File notas_combinado.txt # ps51: une dos ficheros Get-Content -Path notas.txt -Tail 5 | Out-File notas_5.txt # ps59

Get-Contentps33, ps36–ps38, ps44, ps45, ps49–ps52, ps59, ps60

EscribesResultado

Get-Content sintaxis.txt -Tail 3las últimas 3 líneas (como tail)

Select-Stringps34, ps48, ps58

En pocas palabras«Enséñame las líneas que contienen esta palabra». Es el grep de Linux.
Select-String -Path fichero -Pattern texto Select-String -Path sintaxis.txt -Pattern carpeta # ps34 Select-String -Path notas.txt -Pattern "Pablo" # ps48 Select-String -Path notas.txt -Pattern "10" # ps58 systeminfo | Select-String "Tiempo de arranque del sistema" # filtrar la salida de otro comando
Verás (el formato incluye fichero y nº de línea)

Sort-Objectps38, ps46, ps52–ps55, ps60, ps71, ps79, ps80

En pocas palabras«Ordena». Sin nada, ordena el texto de A a Z. Con -Property ordena por una propiedad. -Descending = de mayor a menor.
Get-Content notas.txt | Sort-Object # alfabético Get-ChildItem | Sort-Object -Property Length # por tamaño, pequeño primero Get-ChildItem | Sort-Object -Property Length -Descending # grande primero Get-Process | Sort-Object CPU -Descending # procesos por uso de CPU Get-Service | Sort-Object Name # servicios por nombre

Select-Objectps55, ps73, ps80

En pocas palabras«Quédate solo con…»: los primeros N resultados (-First) o solo ciertas columnas (propiedades).
Get-ChildItem | Sort-Object -Property Length -Descending | Select-Object -First 3 # los 3 más grandes (ps55) Get-Service | Select-Object Name, Status # solo esas 2 columnas, en ese orden (ps73) Get-Process | Sort-Object CPU -Descending | Select-Object -First 5 # los 5 que más CPU usan (ps80)

Get-Service, Start-Service, Stop-Serviceps68–ps76

En pocas palabrasUn servicio es un programa que trabaja en segundo plano (impresión, actualizaciones, red). Get-Service los lista; Start- y Stop-Service los arrancan y paran.
Get-Service # ps68: todos Get-Service | Where-Object Status -eq "Running" # ps69: solo los que están funcionando Get-Service | Where-Object Name -like "*Network*" # ps70: que contengan "Network" Get-Service | Sort-Object Name # ps71: ordenados por nombre Get-Service -Name "wuauserv" # ps72: Windows Update (nombre interno) Get-Service | Select-Object Name, Status # ps73 Get-Service -Name "Spooler" # ps75: cola de impresión Stop-Service -Name "Spooler" # ps74: parar Start-Service -Name "Spooler" # ps76: arrancar
Verás (inventado)
Status Name DisplayName ------ ---- ----------- Running Spooler Cola de impresión Stopped wuauserv Windows Update
Tus fallos: ps74 y ps76 – lo hiciste con Get-Service | Where-Object … | Stop-Service; la solución es directa: Stop-Service -Name "Spooler" / Start-Service -Name "Spooler". En ps68 («todos los servicios en ejecución») la solución es solo Get-Service.

Where-Objectps69, ps70, ps78

En pocas palabras«Déjame pasar solo los que cumplan esto». Como un colador: Where-Object Propiedad -operador valor.
... | Where-Object Propiedad -operador "valor" Get-Service | Where-Object Status -eq "Running" # Status igual a Running Get-Service | Where-Object Name -like "*Network*" # el nombre contiene Network Get-Process | Where-Object Name -like "*Microsoft*" # ps78

Operadores: -eq igual · -ne distinto · -like con comodines * · -gt mayor · -lt menor.

Get-Processps71, ps77–ps80, ps82
